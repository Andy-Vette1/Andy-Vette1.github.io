## 一、 核心概念：问题建模 (Problem Formulation)
在让计算机求解之前，必须将现实世界的问题“翻译”成数学和逻辑模型。这个过程的核心在于**抽象 (Abstraction)**——无情地剥离对达成目标没有实质影响的细节，以防止状态空间爆炸。

### 1. 建模的五大核心要素
* **初始状态 (Initial State)**：问题开始时的确切局面。
* **动作与转移模型 (Actions & Transition Model)**：当前状态下合法的操作，以及操作后会转移到什么新状态。
* **约束条件 (Constraints)**：绝对不能打破的物理或逻辑规则。
* **目标测试 (Goal Test)**：判断当前状态是否满足胜利或结束条件。
* **路径成本 (Path Cost)**：执行动作序列所付出的代价，通常目标是寻找成本最小的路径。

### 2. 建模在实际工程中的权衡
在开发复杂的博弈程序（如中国象棋AI）时，要素的界定往往是模棱两可的。例如，“状态”是否需要包含前几步的历史记录以判断“长将”？如果保留过多细节，内存会撑爆；如果剥离太多，AI 会做出愚蠢决策。工程上通常采用**迭代法**：先建立最简化的原子模型跑通逻辑，再逐步向状态中添加必要的细节特征。

## 二、 关键机制：搜索框架 (Search Frameworks)
搜索框架是算法的“底盘”，决定了算法是否有“记忆”，从而决定了是否会陷入死循环。

### 1. 树搜索 (Tree-Search)
* **机制**：无记忆。只维护一个待探索边界（Frontier / `OPEN list`）。
* **缺陷**：遇到可以走回头路的图（现实大多数问题）时，会把图无限展开成一棵树，极易陷入死循环（如在两个房间内左右横跳）。

### 2. 图搜索 (Graph-Search) 
* **机制**：有记忆。除了待探索边界，还必须维护一个**已探索集合 (Explored Set / `CLOSED list`)**。
* **防绕圈原理**：每次准备扩展新节点前，先查阅 `CLOSED list`。如果该状态以前来过，直接剪枝（忽略）。这与在 Python 中刷算法题时，使用 `visited` 集合来防止图遍历超时的底层逻辑完全一致。

## 三、 核心原理：无信息搜索策略 (Uninformed Search Strategies)
策略是算法的“发动机”，决定了在面对多个待探索节点时，**优先挑选哪一个**。它们必须被装载到上述的“框架”中运行。

### 1. 复杂度评估的三个核心变量
* **$b$ (Branching Factor)**：分支因子。当前状态平均有多少个合法的后续动作。
* **$d$ (Depth)**：目标节点所在的最浅深度（最短步数）。
* **$m$ (Max Depth)**：状态空间中任何路径的最大深度（可能是无限大 $\infty$）。

### 2. 广度优先搜索 (BFS - Breadth-First Search)
* **数据结构**：FIFO 队列（先进先出）。一层一层向外地毯式搜索。
* **时间复杂度**：$O(b^d)$。指数级。
* **空间复杂度**：$O(b^d)$。指数级。**这是 BFS 的致命弱点**。当 $d$ 较大时，内存（等待队列）会瞬间耗尽导致崩溃 (Memoryout)。
* **最优性 (Optimality)**：**仅当所有动作的成本 (Path Cost) 完全相同时，BFS 才能保证找到最优路径。** 如果成本不同，必须使用统一代价搜索 (UCS / Dijkstra)。

### 3. 深度优先搜索 (DFS - Depth-First Search) 
* **数据结构**：LIFO 栈（后进先出）。一条路走到黑，撞南墙再回溯。
* **时间复杂度**：最坏情况 $O(b^m)$（指数级）；最好情况 $O(d)$（线性级，运气好直接命中）。
* **空间复杂度**：$O(bm)$。**这是 DFS 的最大优势**。它只需记住当前路径及其兄弟节点，内存消耗极小（线性级）。
* **完备性 (Completeness)**：在无限深度空间且未使用图搜索框架时，会陷入死循环（不完备）。

### 4. 深度优先迭代加深搜索 (DFID - Depth-First Iterative Deepening) 
* **机制**：用一个 `for` 循环不断放宽深度限制 $L$ ($L=0, 1, 2...$)，每次在限制内跑深度受限搜索 (DLS)。
* **优势融合**：结合了 BFS 的“保证找到最短路径”和 DFS 的“极低内存消耗 ($O(bd)$)”。
* **为什么重复搜索不浪费？**：因为树的节点数量是指数级向下爆炸的。绝大多数节点集中在最底层（只被生成 1 次），顶层被重复生成的节点数量在数学上微不足道（仅增加约 10% 的计算开销）。**在复杂且未知深度的真实工程中，DFID 是最实用、最稳健的盲目搜索策略。**

## 四、 进阶与联系：状态表示与约束满足 (CSP)
当经典搜索算法面临极度复杂的逻辑约束时，需要升级计算机看待“状态”的视角。

### 1. 状态表示的演进
* **原子表示 (Atomic)**：把状态看作不可分割的黑盒。算法只能对比“状态 A 是否等于状态 B”（如 BFS/DFS 中的节点对比）。
* **因子表示 (Factored)**：把状态解剖为一组**变量 (Variables)** 和 **值 (Values)**。算法可以介入状态内部进行逻辑推理（如博弈树推演、机器学习特征输入）。

### 2. 约束满足问题 (CSP - Constraint Satisfaction Problem) 
CSP 是一种将复杂现实问题标准化的填空游戏。它的三大要素：
* **$X$ (Variables 变量)**：需要做决定的对象（例如：四皇后问题中的每一行）。
* **$D$ (Domains 值域)**：每个变量可选的答案池（例如：可以选择放在第 1 到 4 列）。
* **$C$ (Constraints 约束)**：变量之间不可打破的规则（例如：皇后之间不能在同一列或对角线）。

### 3. 回溯算法 (Backtracking Algorithm)
* 求解 CSP 的核心算法。它本质上是 **DFS（深度优先） + 实时约束检查**。
* **机制**：给变量赋值 -> 立即检查是否违反约束 -> 若违反（Deadend），立即撤销该赋值（回溯），尝试下一个值。

## 五、 常见误区与易错点（需重点复习）

### ❌ 误区 1：认为 BFS 和 DFS 是“树搜索”或“图搜索”
* **纠正**：Tree-Search 和 Graph-Search 是底层**框架**（决定了有没有 `visited` 集合来防死循环）。BFS 和 DFS 只是挑选节点的排队**策略**。你完全可以写出一个基于 Graph-Search 框架的 DFS，也可以写出一个基于 Tree-Search 框架的 BFS。两者是自由组合的关系。

### ❌ 误区 2：只要是找最短路径，就无脑用 BFS
* **纠正**：必须满足前提条件——**每一步的代价必须完全相等**（比如走网格迷宫，每走一格代价都是 1）。如果代价不同（如罗马尼亚地图上真实的公里数），使用 BFS 找到的只是“经过城市最少”的路线，而不是“距离最短”的路线。此时必须改用 UCS（Dijkstra）。

### ❌ 误区 3：DFID 每次都要从头搜，计算效率极低
* **纠正**：这是直觉陷阱。因为树形结构下端的节点数量呈指数级庞大，DFID 真正的计算大头都在最后一层。重复计算顶层的开销极小。在内存受限的情况下，这 10% 的时间牺牲换来的是免于内存崩溃的绝对安全。

### ❌ 误区 4：DFS 时间复杂度永远很差
* **纠正**：DFS 的时间非常不稳定。最坏情况下确实是 $O(b^m)$，但在目标密集或运气好的最好情况下，它可以达到惊人的 $O(d)$。它的核心卖点永远是线性的空间复杂度（省内存）。

### Tentative Algorithms (Systematic Search)

#### Heuristic Search

UCS 的问题在于它是盲目搜索（blind search），在 unit-cost 的情况下会向各个方向等量扩展节点，而不是朝着目标方向优先搜索。

Heuristic（启发式）是 domain-dependent 的信息，用来减少搜索量。核心概念是 **h(n)** ：从节点 n 到目标的代价估计（cost-to-goal estimate）。

h(n) 的基本要求：
- h 是从节点到代价的实值函数
- 对所有节点 n，h(n) >= 0
- 对所有目标节点 n，h(n) = 0

h(n) 是用来识别goal的

启发式通常来自 **relaxed problem**（放宽约束后的问题），relaxed problem 的最优解代价可以作为原问题的 heuristic。

**8-Puzzle 的两个经典启发式：**
- h1(n)：misplaced tiles 的数量（放宽为 tile 可以移到任意位置）
- h2(n)：所有 tile 的 Manhattan distance 之和（放宽为 tile 可以移到任意相邻格）
  - 计算每个 tile 的 Manhattan distance 时，**不考虑其他棋子的阻挡，也不考虑空格位置**，只计算该 tile 单独上下左右移动到目标位置所需的步数
- h2 dominates h1，因为 h2(n) >= h1(n) 对所有 n 成立，搜索效率更高

---

#### Relaxed Problems

放宽原问题的约束所得到的问题叫做 relaxed problem。relaxed problem 的最优解代价是原问题的 admissible heuristic，因为放宽约束后解的代价不会高于原问题。

---

#### Heuristic Search:Definitions

三个核心值的直觉理解：

| 符号               | 直觉含义                                |
| ------------------ | --------------------------------------- |
| g(n)               | 已经花了多少（从起点到 n 的实际代价）   |
| h(n)               | 还大概要花多少（从 n 到目标的估计代价） |
| f(n) = g(n) + h(n) | 这条路总共大概要花多少                  |

完整定义：

| 符号                  | 含义                                         |
| --------------------- | -------------------------------------------- |
| k(ni, nj)             | ni 和 nj 之间的最短图距离                    |
| h*(n)                 | n 到所有目标节点的最短距离，即 min{k(n, ti)} |
| g*(n)                 | 从起点 s 到 n 的最优代价，即 k(s, n)         |
| f(n) = g(n) + h(n)    | 经过节点 n 的路径代价估计                    |
| f*(n) = g*(n) + h*(n) | 经过节点 n 的最优路径的真实代价              |

其中：
- **c(n, n')** ：从当前节点 n 到后继 n' 的一步边代价
- **h(n')** ：站在后继节点 n' 上，对它到目标剩余代价的估计

**Heuristic dominance：** 若两个 lower-bounding heuristics h1、h2 满足 h2(n) >= h1(n) 对所有 n 成立，则称 h2 dominates h1。

注意这里比较的是 **heuristic 的质量，不是 OPEN 里节点的优先级** ：
- 选节点时：A\* 选 f 更小的
- 比较 heuristic 好坏时：在不高估的前提下，h 越大越接近真实值 h\*，越有信息量，所以越好

若有多个互不支配的启发式，可取 h(i) = max{h1(i), h2(i), ..., hn(i)}。

---

### GBFS (Greedy Best-First Search)

**思路：** 只看 h(n)，每次扩展 h 值最小的节点，忽略已走过的路径代价。

**Properties：**

| 性质      | 结论                                      |
| --------- | ----------------------------------------- |
| Complete? | Tree-search 下不保证；Graph-search 下保证 |
| Optimal?  | 不保证                                    |
| Time      | O(b^m)                                    |
| Space     | O(b^m)                                    |

**Problems with GBFS：** GBFS 完全忽略 path cost（g(n)），只追求启发式上的"近"，可能找到次优路径甚至陷入局部最优。

贪心算法有越多的h函数，效果越好吗？

---

### A*

**思路：** 结合路径代价与启发式，评估函数为 f(n) = g(n) + h(n)，每次扩展 f 值最小的节点。其余步骤与 UCS 相同。

扩展节点 n 时，对每个后继 n' 计算的是 **tentative g(n') = g(n) + c(n, n')** ，即"到当前节点的代价 + 走到后继的一步边代价"，再加上 h(n') 得到 f(n')：

$$f(n') = g(n) + c(n, n') + h(n')$$

例如在例子中出现的 `7+7`、`7+15` 这种写法，前一个数字是当前节点的 g 值，后一个是一步边代价，两者相加才是后继的 tentative g 值，而不是在重新计算某条旧路径。

扩展过程中还会出现两种情况：
- **dominated** ：如果 OPEN 里已有同一节点的更便宜版本，当前这个更差的候选直接丢弃
- **update** ：如果发现同一节点有更便宜的新路径，则更新 OPEN 里该节点的记录并重新计算优先级

**Admissibility 与 Consistency：**

> **Admissibility（可采纳性）：** h(n) <= h*(n) 对所有节点成立，即 heuristic 可以低估，但不能高估真实最短剩余代价。
> 记忆：宁可少报，不能多报。
> 若满足，A* 可以找到最优解。

> **Consistency（一致性 / 单调性）：** h(n) <= c(n, n') + h(n') 对所有节点 n 及其后继 n' 成立，即相邻节点之间的 heuristic 估计要前后平滑，不能突然大跳。
> 记忆：前后说法不能打架。
> 若满足，A* 对每个扩展节点都已找到最优路径。

admissibility保证A*一定能找到最优解
consistency来提高A*的搜索效率

要理解为什么A*最优？

两者的关系：
- 高估会把真正最优路径伪装成"看起来很贵"，导致 A* 可能先返回次优解
- consistency 比 admissibility 更强：consistent ⇒ admissible
- admissible 不一定 consistent，因为"单个点不高估"不代表"相邻两点之间估计平滑"

**Properties of A\*：**

| 性质      | 结论                              |
| --------- | --------------------------------- |
| Complete? | 是                                |
| Optimal?  | 是（heuristic admissible 时）     |
| Time      | O(b^Δ)，其中 Δ = \|h*(s) - h(s)\| |
| Space     | O(b^Δ)                            |

A\* 会扩展所有 f(n) < C\*（最优解代价）的节点，以及部分 f(n) = C\* 的节点。空间复杂度是 A\* 的主要瓶颈。

### Irrevocable Algorithms (Local Search)

Local search 只保留当前状态（或少数几个状态），不记录路径，适用于时间或空间受限的场景。代价是不保证找到全局最优解。

---

#### Hill Climbing

每次移动到邻居中值最高（或代价最低）的状态，若无改进则停止。
```
function HILL-CLIMBING(problem):
    current = MAKE-NODE(problem.INITIAL-STATE)
    loop:
        neighbor = highest-valued successor of current
        if neighbor.VALUE <= current.VALUE: return current.STATE
        current = neighbor
```

**优点：** 对 concave（单峰）函数可以找到全局最优。

**缺点：** 大多数代价函数不是 concave 的，容易陷入 local maximum、shoulder、flat local maximum 等区域，此时算法无法继续改进。

---

#### Local Beam Search

保留 k 个状态而不是 1 个，每轮生成所有 k 个状态的全部后继，保留其中最好的 k 个继续搜索。

- k=1 时退化为 Hill Climbing
- k 趋近于无穷时接近 BFS
- 可加入随机选择（Stochastic Beam Search）改善多样性
- 仍然可能陷入局部最优

---

#### Simulated Annealing

**思路：** 在 Hill Climbing 基础上引入随机性，允许以一定概率接受"变差"的移动，从而逃离局部最优。概率由温度参数 T 控制，T 随时间降低（cooling schedule）。
```
function SIMULATED-ANNEALING(problem, schedule):
    current = MAKE-NODE(problem.INITIAL-STATE)
    for t = 1 to ∞:
        T = schedule(t)
        if T = 0: return current
        next = a randomly selected successor of current
        ΔE = next.VALUE - current.VALUE
        if ΔE > 0: current = next
        else: current = next with probability e^(ΔE/T)
```

- 若 ΔE > 0（改进），直接接受
- 若 ΔE <= 0（变差），以概率 e^(ΔE/T) 接受：T 越高，接受坏移动的概率越大；T 越低，越趋近于 Hill Climbing
- 若 T 下降足够慢，SA 以概率趋近于 1 找到全局最优

**应用：** VLSI layout、airline scheduling、job-shop scheduling 等。

---

#### Genetic Algorithms

**思路：** 模拟自然进化，维护一个由 k 个染色体（状态）组成的种群，通过选择、交叉、变异产生下一代。

**基本步骤：**
1. **Selection（选择）：** 按 fitness function 的比例概率选择亲代，fitness 越高被选中概率越大
2. **Crossover（交叉）：** 随机选择交叉点，将两个亲代的基因片段拼接产生后代
3. **Mutation（变异）：** 以小概率随机改变某些基因

**8-Queens 示例：**
- 染色体：8 个基因，每个基因表示对应列中皇后所在的行号
- Fitness function：non-attacking pairs 的数量（最大 28）
- 选择概率正比于 fitness 值

GA 的优势在于通过 crossover 可以组合来自不同状态的有益"building blocks"，探索能力强于 Hill Climbing 和 Beam Search。

## Week 5 Knowledge Representation I

### 核心问题
如何让 AI agent 用逻辑来表示和推理关于世界的知识？

---

### 1. Knowledge Base（知识库）

- **Knowledge Base（KB）**：一个装着逻辑句子的集合，描述关于世界的事实和规则
- **Inference Engine（推理引擎）**：通用推理算法，从 KB 推出结论
- 两个操作：
  - **TELL**：往 KB 加入新信息
  - **ASK**：向 KB 提问，推理引擎自动推出答案

---

### 2. Logic in General（逻辑基础）

- **Syntax（语法）**：定义什么样的句子是合法的
- **Semantics（语义）**：定义句子在什么情况下为真或假
- **Model（模型）**：一个可能的世界，给所有变量赋了具体的真/假值
  - 如果句子 α 在模型 m 里为真，称 m 满足 α

---

### 3. Entailment（蕴含）

- 写作 α ╞ β
- 意思：在所有 α 为真的模型里，β 也为真
- α 是更强的断言：M(α) ⊆ M(β)
- **注意**：α 为假时，不管 β 真假，蕴含关系不受影响
- 唯一让 α ╞ β 不成立的情况：α 为真但 β 为假

---

### 4. Inference（推理）

- **KB ├i α**：用推理程序 i，从 KB 推导出了 α
- **Soundness（可靠性）**：如果 KB ├i α，那么 KB ╞ α（推出来的都是真的，不乱推）
- **Completeness（完备性）**：如果 KB ╞ α，那么 KB ├i α（该推的都能推，不遗漏）
- 符号区别：
  - ╞ 是语义层面（数学上是否成立），没有 i
  - ├i 是语法层面（计算过程），有 i

---

### 5. Propositional Logic（命题逻辑）

#### 语法
- **命题符号**：P、Q、A、B 等，是最基本的原子句子，只能为真或假
- **句子**：由命题符号和连接符组合而成

#### 5个逻辑连接符（优先级从高到低）

| 符号 | 名称          | 读法    |
| ---- | ------------- | ------- |
| ¬    | Negation      | not     |
| ∧    | Conjunction   | and     |
| ∨    | Disjunction   | or      |
| ⇒    | Implication   | implies |
| ⇔    | Biconditional | iff     |

#### 语义（5条规则）
- ¬S 为真，当且仅当 S 为假
- S1 ∧ S2 为真，当且仅当 S1 和 S2 都为真
- S1 ∨ S2 为真，当且仅当 S1 或 S2 至少一个为真
- S1 ⇒ S2 为真，除非 S1 为真且 S2 为假
- S1 ⇔ S2 为真，当且仅当 S1⇒S2 且 S2⇒S1 都为真

#### ⇒ 的理解
- 把 ⇒ 理解成**承诺**，不是因果关系
- S1 ⇒ S2 ≡ ¬S1 ∨ S2
- 唯一为假的情况：S1 为真，S2 为假

---

### 6. Equivalence, Validity, Satisfiability

#### Logical Equivalence（逻辑等价）
两个句子在所有模型里真值完全相同，写作 α ≡ β

**重要等价关系：**
- **Implication elimination**：P ⇒ Q ≡ ¬P ∨ Q
- **De Morgan**：¬(P ∧ Q) ≡ ¬P ∨ ¬Q
- **De Morgan**：¬(P ∨ Q) ≡ ¬P ∧ ¬Q
- **Double negation**：¬(¬P) ≡ P
- **Contraposition**：P ⇒ Q ≡ ¬Q ⇒ ¬P
- **Biconditional elimination**：P ⇔ Q ≡ (P ⇒ Q) ∧ (Q ⇒ P)

#### Validity（有效性）
- 句子在**所有模型**里都为真，叫 valid（重言式/tautology）
- 例：P ∨ ¬P 永远为真
- **Deduction Theorem**：α ╞ β 当且仅当 α ⇒ β 是 valid 的

#### Satisfiability（可满足性）

| 情况          | 意思               | 例子   |
| ------------- | ------------------ | ------ |
| Valid         | 所有模型里都为真   | P ∨ ¬P |
| Satisfiable   | 至少一个模型里为真 | P ∧ Q  |
| Unsatisfiable | 所有模型里都为假   | P ∧ ¬P |

**重要关系：**
- α 是 valid ↔ ¬α 是 unsatisfiable
- α 是 satisfiable ↔ ¬α 不是 valid
- **α ╞ β ↔ α ∧ ¬β 是 unsatisfiable**（反证法基础）

---

### 7. Proof Methods（证明方法）

#### Model Checking（模型检验）
- 枚举所有 2ⁿ 个模型，直接检查语义
- 缺点：n 大时非常慢

#### Application of Inference Rules（推理规则）
- 用规则一步步从已知句子推出新句子
- Proof = 一系列推理规则的应用

---

### 8. Inference Rules（推理规则）

#### Modus Ponens（肯定前件）
```
P
P ⇒ Q
-------
Q
```
已知 P 为真，且 P ⇒ Q，推出 Q

#### Modus Tollens（否定后件）
```
¬Q
P ⇒ Q
-------
¬P
```
已知 Q 为假，且 P ⇒ Q，推出 P 为假

#### And Elimination（合取消除）
```
P ∧ Q
-------
P 或 Q
```

#### Chaining（链式推理）
```
P ⇒ Q
Q ⇒ R
-------
P ⇒ R
```

---

### 9. CNF（Conjunctive Normal Form，合取范式）

一堆子句用 ∧ 连起来，每个子句里面是字面量用 ∨ 连起来。

例：(¬A ∨ B ∨ C) ∧ (¬B ∨ A) ∧ (¬C ∨ A)

#### 转换步骤
1. **消去 ⇔**：α ⇔ β → (α ⇒ β) ∧ (β ⇒ α)
2. **消去 ⇒**：α ⇒ β → ¬α ∨ β
3. **¬ 往里移**：用 De Morgan 和双重否定
4. **分配律**：∧ 分配到 ∨ 里面

---

### 10. Resolution（归结）

如果两个子句里有一对互补的字面量，消掉后合并成新子句。

```
¬P ∨ Q
P ∨ R
-------
Q ∨ R
```

#### Resolution Refutation（归结反驳）
证明 KB ╞ α 的步骤：
1. 把 **¬α** 加入 KB
2. 不断应用 Resolution
3. 推出 **NIL（空子句）** → 产生矛盾 → α 一定为真

---

### 11. Horn Clauses（霍恩子句）

| 类型            | 正字面量数量 | 例子                   |
| --------------- | ------------ | ---------------------- |
| Definite Clause | 恰好 1 个    | (A ∧ B) ⇒ C            |
| Horn Clause     | 最多 1 个    | (A ∧ B) ⇒ C 或 ¬A ∧ ¬B |

- 所有 Definite Clause 都是 Horn Clause
- KB 全为 Horn Clause 时，推理复杂度是线性的
- 支持 Forward 和 Backward Chaining

---

### 12. Forward & Backward Chaining

|      | Forward Chaining | Backward Chaining  |
| ---- | ---------------- | ------------------ |
| 起点 | 已知事实         | 目标               |
| 方向 | 事实 → 目标      | 目标 → 事实        |
| 特点 | 数据驱动         | 目标驱动           |
| 缺点 | 可能推出无关结论 | 可能重复检查子目标 |

两者都是 sound 和 complete 的（针对 Horn KB）。

---

### 13. 命题逻辑的局限性

- 表达能力有限，无法表达通用陈述
- 例：无法用一句话表达"所有人都会死"，只能逐个列举
- 解决方案：**一阶逻辑（First-order Logic）**，下节课内容

#### 命题逻辑 vs 一阶逻辑

|                | 命题逻辑         | 一阶逻辑               |
| -------------- | ---------------- | ---------------------- |
| 基本单位       | 完整命题（P、Q） | 对象和关系（Human(x)） |
| 能否表达"所有" | 不能             | 能（∀）                |
| 能否表达"存在" | 不能             | 能（∃）                |
| 表达能力       | 有限             | 强大                   |


## Week 6 Knowledge Representation II

### 一、从命题逻辑到FOL的动机

命题逻辑的问题：每个具体情况都要单独写规则，无法泛化。比如4×4格子世界，16个方格就要写16条规则。

FOL的解决方案：用变量和量词，一条规则覆盖所有情况。

三个核心概念的对应：

- Logic = 思考（推理）
- Search = 规划（路径）
- Agent = 行动

---

### 二、FOL的世界观

FOL假设世界由三种东西组成：

- **对象（Objects）**：people, houses, numbers, colors...
- **关系（Relations）**：red, round, brother_of, bigger_than...
- **函数（Functions）**：father_of, best_friend, plus...

这是一种**结构化表示（Structured representation）**，比命题逻辑的事实化表示（Factored representation）表达能力更强。

---

### 三、FOL语法元素

**term（项）** — 代表对象，没有真假值，三种形式：

- 常量（Constant）：`1, 2, StartX`
- 变量（Variable）：`x, y, u`
- 函数（Function）：`right(x,y), up(1,1), g(u)`

**atom（原子式）** — 谓词加上若干term，有真假值：

```
BREEZE(x, y)
PIT(1, 2)
ADJACENT(1,1, 1,2)
```

**literal（文字）** — atom或其否定：

```
BREEZE(x,y)     ← 正文字
¬BREEZE(x,y)    ← 负文字
```

**ground literal** — 不含变量的literal：

```
BREEZE(1,1)     ← ground
¬PIT(2,3)       ← ground
BREEZE(x,y)     ← 不是ground
```

**clause（子句）** — literal的析取：

```
PIT(x,y) ∨ ¬BREEZE(z,w)
```

**CNF（合取范式）** — 子句的合取：

```
(¬EASY(u) ∨ ENROLLED(g(u),u)) ∧ (¬EASY(u) ∨ HAPPY(g(u)))
```

层次关系：

```
term       → 东西（常量/变量/函数）
atom       → 谓词(term, term, ...)
literal    → atom 或 ¬atom
clause     → literal ∨ literal ∨ ...
CNF        → clause ∧ clause ∧ ...
```

---

### 四、Well Formed Formulas（wff）

wff是"合法的FOL句子"，保证表达式有真假值，推理才能建立在上面。

#### 构造规则（6条）

1. 任何合法的atom是wff（基础）
2. wff的否定（¬）是wff
3. 两个wff的合取（∧）是wff
4. 两个wff的析取（∨）是wff
5. 两个wff构成的蕴含（⇒）是wff
6. 对wff加量词（∀或∃）是wff

#### 常见错误

- `¬f(A)` — 不是wff，f(A)是term，没有真假值，不能被否定
- `f(P(A))` — 不是wff，P(A)是atom，不能作为函数参数
- `∀P P(A)` — 不是wff，∀只能量化变量，不能量化谓词符号

**判断方法：** 从最里层往外，每一步必须符合上面某条规则。关键原则：**∧∨¬⇒和量词只能作用在wff上，不能作用在term上。**

---

### 五、量词（Quantification）

量词的作用是明确变量的范围，没有量词约束的变量是不完整的。

**∀（全称量词）** — 对所有对象成立：

```
∀x ∀y [¬BREEZE(x,y) ⇒ SAFE(up(x),y)]
```

**∃（存在量词）** — 存在某个对象使得成立：

```
∀x∀y(Breeze(x,y) ⇒ ∃u∃v(Adjacent(x,y,u,v)∧Pit(u,v)))
```

---

### 六、量词嵌套顺序

顺序不同，意思完全不同。

**∀在外，∃在内：**

```
∀x∀y(Breeze(x,y) ⇒ ∃u∃v(Adjacent(x,y,u,v)∧Pit(u,v)))
```

"对每个有微风的格子，各自存在某个相邻格有陷阱"（每个格子的陷阱可以不同，合理）

**∃在外，∀在内：**

```
∃u∃v ∀x∀y(Breeze(x,y) ⇒ (Adjacent(x,y,u,v)∧Pit(u,v)))
```

"存在同一个格子，使所有有微风的格子都与它相邻且有陷阱"（几乎不可能为真）

规律：**∃越靠外，约束越强，越难为真。**

---

### 七、FOL等价式

**量词与否定：**

```
¬(∃x)P(x) ≡ (∀x)[¬P(x)]
¬(∀x)P(x) ≡ (∃x)[¬P(x)]
```

规律：¬往里推碰到量词，∀和∃互换。

**量词与连接词：**

```
(∀x)[P(x) ∧ Q(x)] ≡ (∀x)P(x) ∧ (∀y)Q(y)
(∃x)[P(x) ∨ Q(x)] ≡ (∃x)P(x) ∨ (∃y)Q(y)
```

**注意：以下两个不等价：**

```
(∀x)[P(x) ∨ Q(x)]  ≠  (∀x)P(x) ∨ (∀y)Q(y)
```

∀不能对∨分配，∃不能对∧分配。

---

### 八、推理规则

**Modus Ponens：**

```
[P ∧ P⇒Q] → Q
```

**Modus Tollens：**

```
[¬Q ∧ P⇒Q] → ¬P
```

**全称特化（Universal Specialization）：**

```
∀x W(x) → W(A)，其中A是常量
```

把通用规则实例化为具体常量，常与Modus Ponens组合使用。

---

### 九、代入（Substitution）

把变量替换成term（常量、变量或函数）。

写法：

```
{x|1, y|1}   ← 把x替换为1，把y替换为1
```

**关键：所有替换同时应用，不是顺序应用。**

例子：

```
P(w,y,g(z),x) 经 {x|g(y), y|h(z), z|x}
→ P(w, h(z), g(x), g(y))
```

#### 代入的组合（Composition）

s₁s₂表示先应用s₁再应用s₂，计算方法：

1. 对s₁的每个项应用s₂
2. 把s₂中s₁没有的变量直接加入
3. s₂中s₁已有的变量丢掉

**重要性质：**

- 满足结合律：(s₁s₂)s₃ = s₁(s₂s₃)
- **不满足交换律：s₁s₂ ≠ s₂s₁**

---

### 十、合一（Unification）

找到代入θ，使两个表达式应用θ后完全相同。

#### 合一的三个条件

- 谓词符号必须相同
- 参数个数必须相同
- 两个表达式不能有相同变量名

#### 例子

```
E1 = PIT(1, y)，E2 = PIT(1, 2)
合一代入：{y|2}

E1 = KNOWS(1, y)，E2 = KNOWS(x, 2)
合一代入：{y|2, x|1}
```

#### 最一般合一（mgu）

约束最少的合一代入：

```
P(x,f(y)) 与 P(x,f(B))
普通合一：{x|A, y|B}（多约束了x）
mgu：{y|B}（最少约束）
```

#### 合一算法（UNIFY）

递归拆解表达式，逐层对齐：

- 两个表达式相同 → 返回当前θ
- 遇到变量 → 调用UNIFY-VAR
- 复合表达式 → 先合一函数名，再合一参数列表
- 列表 → 先合一第一个元素，再合一剩余部分

UNIFY-VAR处理变量时需检查occur check（变量不能出现在要替换的表达式里，防止循环）。

---

### 十一、把wff转换成子句（9步）

目的：消解法只能处理CNF子句，所有wff必须先转换。

1. 消去 ⇒（用 `A⇒B ≡ ¬A∨B`）
2. 把 ¬ 往里推，缩小辖域（用de Morgan和量词等价式）
3. 标准化变量名（每个量词用不同变量）
4. **Skolem化（消去 ∃）**
5. 把所有 ∀ 移到最前面
6. 转成CNF（用分配律展开）
7. 消去 ∀（子句里变量默认全称）
8. 消去 ∧（拆成独立子句）
9. 重命名变量（每个子句变量独立）

#### Skolem化（第4步）

∃在∀内部 → 用Skolem函数替换，参数是外层所有∀变量：

```
∀x ∃y P(x,y)  →  P(x, g(x))
```

∃不在任何∀内 → 用Skolem常量替换：

```
∃y P(y)  →  P(A)
```

#### 完整例子

原式：

```
∀u[EASY(u) ⇒ ∃s[ENROLLED(s,u) ∧ HAPPY(s)]]
```

步骤1，消去⇒：

```
∀u[¬EASY(u) ∨ ∃s[ENROLLED(s,u) ∧ HAPPY(s)]]
```

步骤4，Skolem化（∃s在∀u内，用函数g(u)）：

```
∀u[¬EASY(u) ∨ [ENROLLED(g(u),u) ∧ HAPPY(g(u))]]
```

步骤6，转CNF：

```
∀u[[¬EASY(u) ∨ ENROLLED(g(u),u)] ∧ [¬EASY(u) ∨ HAPPY(g(u))]]
```

步骤7-9，消∀、消∧、重命名：

```
子句1.1：¬EASY(u₁) ∨ ENROLLED(g(u₁),u₁)
子句1.2：¬EASY(u₂) ∨ HAPPY(g(u₂))
```

### 十二、消解法（Resolution）

#### 基本规则

两个子句有互补文字（一正一负），消掉互补对，剩下的合并：

```
子句1：A ∨ L
子句2：B ∨ ¬L'
若L和L'可合一，合一代入为θ
消解式：(A ∨ B)θ
```

#### 消解反驳法（Resolution Refutation）

1. 把所有已知条件转成CNF子句
2. 否定目标，转成CNF子句加入集合
3. 反复对子句两两消解，产生新子句
4. 推出空子句（NIL）→ 证明完成

原理：假设目标为假，若推出矛盾，说明目标必须为真。

#### 完整例子

已知：

1. 如果一门课简单，那存在某个选了它的学生是快乐的
2. 如果一门课有期末考试，那选了它的学生没有一个是快乐的

目标：证明如果一门课有期末考试，那它就不是简单的课。

转换后的子句：

```
1.1：¬EASY(u₁) ∨ ENROLLED(g(u₁),u₁)
1.2：¬EASY(u₂) ∨ HAPPY(g(u₂))
2：  ¬HASFINAL(u₃) ∨ ¬ENROLLED(s₃,u₃) ∨ ¬HAPPY(s₃)
3'.1：HASFINAL(A)       ← 否定目标得到
3'.2：EASY(A)           ← 否定目标得到
```

消解过程：

```
3'.1 + 2  → {u₃|A}        → 4：¬ENROLLED(s₃,A) ∨ ¬HAPPY(s₃)
4    + 1.2 → {s₃|g(u₂)}   → 5：¬ENROLLED(g(u₂),A) ∨ ¬EASY(u₂)
5    + 1.1 → {u₂|A, u₁|A} → 6：¬EASY(A)
6    + 3'.2               → NIL
```

推出NIL，证明完成。

---

### 十三、消解策略

用来控制消解顺序，提高效率，不影响正确性：

**Unit Preference（单元偏好）：** 优先选含unit clause（单literal子句）的消解，产生更短的子句，更快逼近NIL。Unit Resolution是更严格的版本：每次必须有一方是unit clause。

**Set of Support（支持集）：** 每次消解至少用到支持集里的一个子句，通常把否定目标作为初始支持集，避免已知条件之间无意义的互相消解。

**Input Resolution（输入消解）：** 每次消解必须有一方是原始输入子句，限制搜索空间。

**Subsumption（包容）：** 删除被更通用子句包含的子句。如已有 `PIT(x,y)`，则 `PIT(1,2)` 多余，删掉。

---

### 十四、FOL的三种应用

**定理证明（Theorem Proving）：** 把已知事实和规则转成子句，用消解反驳法证明目标。

**问答系统（Question Answering）：** 目标是 `∃x BOSSOF(Joe-Smith, x)`，消解推导过程中合一代入里的x值就是答案。

**规划（Planning）：** 用FOL写通用规则，通过推理判断哪些格子安全，再结合搜索算法规划路径：

```
Breeze(x,y) ⇒ ∃u∃v Adjacent(x,y,u,v) ∧ Pit(u,v)
¬Breeze(x,y) ⇒ ∀u∀v (Adjacent(x,y,u,v) ⇒ ¬Pit(u,v))
¬Pit(x,y) ⇒ Safe(x,y)
```
